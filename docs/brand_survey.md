# 브랜드 확장 조사 대장

어떤 프랜차이즈가 영양정보·가격을 공개하는지 조사한 결과와, 그 조사를 반복 가능하게 만든 방법.

- 대장 파일: `data/brand_survey.csv`
- 갱신 스크립트: `scripts/survey_brands.py`

## 왜 대장을 따로 만들었나

브랜드를 늘리려면 "이 브랜드가 영양정보를 공개하는가"부터 확인해야 하는데, 이걸 매번 즉흥적으로
조사하면 **같은 브랜드를 두 번 조사하거나, 왜 탈락시켰는지 잊어버린다.** 실제로 조사해보니
탈락 사유가 브랜드마다 제각각이었다(영양정보 자체가 없음 / 이미지로만 공개 / 팝업이 빈 페이지 /
도메인 접근 불가 등). 이 판단 근거를 남겨두지 않으면 나중에 재검토가 불가능하다.

그래서 조사 결과를 CSV 대장으로 관리하고, 새 브랜드를 추가할 때마다 스크립트를 다시 돌려
갱신하는 구조로 만들었다.

## 사용법

새 브랜드를 조사 대상에 넣으려면 `scripts/survey_brands.py`의 `PROBE_TARGETS`에 추가한다:

```python
PROBE_TARGETS = {
    "브랜드명": ("카테고리", ["후보 URL 1", "후보 URL 2", ...]),
}
```

그리고 실행하면 `data/brand_survey.csv`가 통째로 갱신된다.

```bash
python scripts/survey_brands.py
```

## 자동 프로브 + 수동 확인의 병합

스크립트는 두 종류의 정보를 합쳐서 CSV를 만든다.

**자동 프로브** — 후보 URL을 순서대로 가져와서 HTML에 영양 키워드(열량/kcal/나트륨/단백질/당류/
포화지방 등)가 몇 종 있는지 센다. 4종 이상이면 `viable`, 1~3종이면 `partial`, 0종이면 `unknown`.

**수동 확인(`MANUAL_FINDINGS`)** — 자동 프로브로는 판정할 수 없는 브랜드를 브라우저로 직접 확인한
결과. **자동 프로브 결과를 덮어쓴다.**

수동 확인이 필요한 이유는 명확하다. 버거킹·KFC·교촌 같은 사이트는 JS로 렌더링해서 HTML만 받아보면
영양 키워드가 하나도 안 나온다. 실제로 버거킹은 자동 프로브로는 "영양정보 없음"으로 보이지만,
브라우저로 확인하니 `BKR0634.json` API에 영양정보와 가격이 모두 있었다. 자동 프로브만 믿으면
이런 브랜드를 잘못 탈락시킨다.

CSV의 `notes` 컬럼에 `[수동확인]` 접두사가 붙은 행이 브라우저로 검증한 것이다.

## status 값의 의미

| status | 뜻 |
|---|---|
| `adopted` | 이미 파이프라인에 포함되어 크롤링 중 |
| `viable` | 영양정보 확보 가능. 크롤러만 만들면 됨 |
| `rejected` | 공식 채널에 영양정보가 없어서 불가 |
| `unknown` | 판정 보류 — 접근 실패했거나 JS 렌더링이라 브라우저 확인 필요 |

`unknown`은 "영양정보가 없다"가 아니라 **"아직 확인 못 했다"**는 뜻이다. 이 구분이 중요한 이유는,
`rejected`는 재조사할 필요가 없지만 `unknown`은 재조사하면 살아날 수 있기 때문이다.

### 재조사 필요 26곳

대부분 두 가지 사유다.

1. **JS 렌더링** (피자헛·파리바게뜨·미스터피자·설빙 등) — HTML만으론 판정 불가. 브라우저 확인 필요
2. **접근 실패** (파파존스·타코벨·쉐이크쉑·푸라닭 등) — URL 경로를 못 찾았거나 도메인 응답 없음

특히 **KFC와 교촌치킨은 가격이 확인된 브랜드**라 우선순위가 높다. KFC는 주문 페이지에 가격이
표시되고("복버켓 16,400") "영양정보표 및 원산지 정보" 링크도 있는데, 그 링크 내용을 아직 확인하지
못했다.

## SSL 검증 우회에 대해

국내 프랜차이즈 사이트 중 인증서 체인이 불완전한 곳이 많아서, 검증 실패 시 한 번 더 검증 없이
시도하도록 했다. 이 우회로 커피빈 등이 회복됐다.

조사용 스크립트에 한정한 판단이다 — 공개 페이지를 읽기만 하고, 여기서 얻은 데이터를 신뢰 경계
안으로 들이지 않는다. **실제 크롤러를 만들 때는 브랜드별로 인증서 문제를 따로 확인해야 한다.**

## 가격 데이터에 대한 결론

당초 가격 기반 기능(슈링크플레이션 탐지, 외식물가지수 대조)을 검토했으나, **가격과 영양정보를
함께 제공하는 브랜드는 버거킹·배스킨라빈스 2곳뿐**이다.

- 맥도날드: 영양 API에 `price` 필드가 있으나 179개 전부 `null`이고, 공식 메뉴 페이지에도 가격 표기가 없다
- 스타벅스·BHC·이디야·빽다방·커피빈·할리스·포케올데이·도미노피자: 영양정보만 있고 가격 없음
- 굽네치킨·한솥도시락: 가격은 있으나 영양정보가 없어 대상이 아님
- KFC·교촌치킨: 가격은 확인됐으나 영양정보 판정 보류

프랜차이즈가 가격을 공시하지 않는 건 구조적 이유로 보인다 — 일반매장과 특수매장(공항·휴게소·
터미널)의 가격이 다르고, 배달가와 매장가도 다르기 때문에 단일 가격을 공시하기 어렵다.

**2곳으로는 슈링크플레이션 분석이나 물가지수 대조가 성립하지 않는다.** 공식 채널 외의 경로는
`docs/price_data_options.md` 참고.
